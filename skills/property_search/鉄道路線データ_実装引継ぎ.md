# 通勤アクセスマップ 実路線データ化 — 実装引継ぎ書

**この文書を読んでいるのはローカル環境で実行されているClaude Code（クラウド版の自分と同一人格・別セッション）です。**
クラウド版セッションはネットワークポリシーによりSUUMO・Google Maps・国土数値情報サイト等の外部アクセスが
できないため、ネットワークアクセスが可能なあなた（ローカル環境）に以下の作業を引き継ぎます。

**方針**: 以下の手順を読み、ブロッカーが無い限り**Step 5(コミット・プッシュ)まで自分の判断で最後まで
進めてください**。ユーザーに逐一確認を取る必要はありません（このタスクの大枠はユーザーと合意済みです）。
ただし、以下のような場合は作業を止めてユーザーに確認してください:
- 国土数値情報のダウンロードでライセンス上の懸念が生じた場合
- 生成した地図を目視確認して明らかにおかしい（路線が繋がっていない、位置がズレている等）場合
- 想定より作業量が大きく膨らみそうな場合（例: 列名が全く推定と違い、大幅な手動対応が必要など）

## 0. 背景（このタスクの経緯）

物件比較サイトの「大手町通勤アクセスマップ」は、各物件の最寄り駅を大手町駅から**直線**で結んで
描画していたが、以下の問題が指摘された：

1. （別問題・解決済み）ジオコーディングの誤りで関東地方外に駅がプロットされる → 修正済み
2. 路線ごとに大手町から各駅への**直線**を引いているため、実際の鉄道路線の形（都心部で複数路線が
   並走してから分岐する等）を反映しておらず、視覚的に「放射状の線が多すぎる」印象になっていた

一度 Google Maps Directions API を使って通勤時間を実測しようとしたが、Google側の問題で断念した経緯がある
（別件・本タスクとは無関係）。今回は **APIキー不要・無料の国土交通省オープンデータ**を使うため、
その種のサービス依存リスクは低い。

## 1. 実装済みの内容（① 〜 ④ に相当、クラウド版セッションで完了済み）

以下はすでにコード化・コミット済みです。あなたが行うのは**⑤ 実データの取得と投入**です。

| ファイル | 内容 |
|---|---|
| `skills/property_search/build_rail_lines.py` | 国土数値情報「鉄道データ(N02)」を読み込み、関東圏に絞り込み、`properties.js`が使っている路線名（29種類）ごとにジオメトリを統合・簡略化して `rail_lines.js` を生成するスクリプト。**ダミーデータでロジック検証済み**（路線名マッチング・関東圏クリップ・区間結合・JS出力すべて動作確認済み） |
| `rail_lines.js` / `物件比較アプリ/rail_lines.js` | 上記スクリプトの出力先。現時点では `const railLinesData = {};`（空）のプレースホルダーをコミット済み |
| `index.html` / `物件比較アプリ/index.html` | `<script src="rail_lines.js"></script>` を `properties.js` の後・`app.js` の前に追加済み |
| `app.js` / `物件比較アプリ/app.js` | `updateMapData()` 内の路線描画ロジックを変更済み。**`railLinesData[路線名]` にジオメトリがあればそれを描画し、無ければ従来通り直線で代用する**フォールバック構造になっている |

→ つまり、**あなたが `rail_lines.js` を実データで上書きしてコミットするだけで、既存コードの変更なしにマップの見た目が改善される**設計です。

## 2. あなたが行う作業（Step 1〜5）

### Step 1: 環境準備

```bash
git fetch origin main
git checkout main
git pull origin main

pip install geopandas shapely pyogrio requests beautifulsoup4
```

### Step 2: 国土数値情報「鉄道データ(N02)」を取得する

1. https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02.html を開く（最新年度のページに自動転送される場合あり）。
2. 全国データ（1ファイル）が提供されていればそれを、無ければ関東の1都6県（東京・神奈川・埼玉・千葉・茨城・群馬・栃木）分をダウンロードする。
   形式は Shapefile (.shp一式) または GeoJSON、どちらでも `build_rail_lines.py` は読み込める（geopandasが両対応）。
3. ダウンロードしたzipを展開し、`.shp`（Shapefileの場合は`.shp .shx .dbf .prj`が同じフォルダに揃っていること）の場所を控える。
   置き場所の例: `skills/property_search/ksj_data/`（このフォルダは`.gitignore`に追記して生データ自体はコミットしない。**コミットするのは加工済みの`rail_lines.js`のみ**）
4. **利用規約を確認**: 国土数値情報のデータは無償で二次利用可能だが、出典表示が求められる場合がある。
   ダウンロードページに記載の利用条件を確認し、Step 4のREADME/index.htmlへのクレジット表記に反映すること。

### Step 3: 属性列を確認する

```bash
python skills/property_search/build_rail_lines.py --input skills/property_search/ksj_data/<ファイル名>.shp --inspect
```

出力される列一覧・サンプル値を見て、「路線名」列と「事業者名(会社名)」列を特定する。
（想定される列名は `N02_003`=路線名, `N02_004`=会社名だが、データのバージョンにより異なる可能性があるため必ず実データで確認すること）

### Step 4: 本実行し、マッチ率を確認する

```bash
python skills/property_search/build_rail_lines.py \
    --input skills/property_search/ksj_data/<ファイル名>.shp \
    --line-col <Step3で確認した列名> \
    --operator-col <Step3で確認した列名>
```

標準エラー出力の最後に「マッチした路線 (n/29)」「未マッチの路線」が表示される。

- **未マッチ路線があっても即エラーではない**（app.js側が自動的に直線描画へフォールバックするため）。ただし、
  できるだけ多くマッチさせたい。未マッチ路線は多くの場合「事業者名の略称違い」（例: SUUMO表記は
  `東武伊勢崎線`だがKSJ側は`伊勢崎線`のみで事業者名が`東武鉄道`、等）が原因なので、
  `build_rail_lines.py` 冒頭の `MANUAL_LINE_NAME_MAP` に対応関係を追記して再実行する。
- 目安として **7割程度（20/29路線）以上マッチすれば十分な改善効果**があると考えられる。全路線のマッチを
  無理に追求して時間をかけすぎる必要はない（未マッチ分は今まで通りの直線描画のままなので、悪化はしない）。

### Step 5: 動作確認・クレジット表記・コミット・プッシュ

1. ローカルで `index.html` をブラウザで直接開き（`file://` で可）、「アクセスマップ」タブを開いて目視確認する。
   - 路線が関東地方の実際の位置に沿って描画されているか
   - 明らかに不自然な形（原点に戻る、大きく飛ぶ等）になっていないか
   - 問題があれば `--simplify-tolerance` を調整するか、該当路線をMANUAL_LINE_NAME_MAPから一旦除外して再実行
2. Step 2で利用規約上クレジット表記が必要と分かった場合、`index.html`のLeaflet属性表示
   （`L.tileLayer`の`attribution`オプション、`app.js`内）に「国土交通省 国土数値情報（鉄道データ）」等を追記する。
3. 生データ用フォルダ（例: `skills/property_search/ksj_data/`）を`.gitignore`に追記し、コミット対象から除外する。
4. 以下の要領でコミット・プッシュする（このプロジェクトの規約: 基本はmainブランチで直接作業）。

```bash
git add rail_lines.js "物件比較アプリ/rail_lines.js" .gitignore index.html "物件比較アプリ/index.html"
git commit -m "国土数値情報の実路線データで通勤アクセスマップを描画"
git push origin main
```

（GitHub Pages反映まで数分。 https://day0817.github.io/Moving/ で確認可能）

## 3. 参考: `railLinesData` のデータ形式

`rail_lines.js` は以下の形式のプレーンJSファイル（`properties.js`と同じ、`<script src>`読み込み前提。fetchは使わない）。

```js
const railLinesData = {
  "東武伊勢崎線": { "type": "LineString", "coordinates": [[139.77, 35.70], [139.79, 35.75], ...] },
  "ＪＲ常磐線": { "type": "MultiLineString", "coordinates": [[[...]], [[...]]] }
  // ...路線名 -> GeoJSONジオメトリ の辞書。キーはproperties.js内の`line`フィールドと完全一致させること
};
```

`app.js`側は `railLinesData[路線名]` が存在すればそれを`L.geoJSON`で描画し、無ければ従来の直線描画にフォールバックする。
このデータ形式・キー名を変更する場合は`app.js`側の対応する処理も合わせて修正すること。
